# Pre-publish article checklist

Mark each `ok`, `issue` or `cannot tell`. Report the result in the thread note.

## Content
- [ ] The article answers the query's intent (learn, compare, buy, fix) and does not wander.
- [ ] First paragraph answers the question or states the result.
- [ ] Adds something the existing top results do not (own experience, data, a clearer method). If not, say so.
- [ ] Every fact has a source or is a `[fill: ...]` the user will resolve.
- [ ] Steps were actually tried, or the text says they were not.
- [ ] No banned phrases (see writing-rules.md); no padding; no repeated points.

## On the page
- [ ] Title about 60 characters or fewer; keyword near the front.
- [ ] Meta description about 155 characters.
- [ ] One H1; H2 order follows the outline; headings are descriptive.
- [ ] Slug short and readable.
- [ ] Primary keyword appears naturally in title, first paragraph and one H2.
- [ ] Images have alt text; file sizes are sensible.

## Links
- [ ] 2 to 5 internal links, to pages that exist, with descriptive anchors.
- [ ] Pages that should link to this article are listed (the user adds them after publishing).
- [ ] Outbound links open real, relevant sources.

## Technical (user or developer does these on the site)
- [ ] Page is in the sitemap and not blocked by robots rules or a noindex tag.
- [ ] Canonical URL is correct.
- [ ] Structured data added if the site uses it for this page type.
- [ ] Page loads fast on mobile.

## Hand-over
- [ ] `[fill: ...]` gaps listed for the user.
- [ ] Row set to `review` with a thread note.
